# OffHours saturation boundary

**Finding:** `pilot-v2` is the hardest tested OffHours ruler Devin GLM-5.2 can
resolve reliably. The immediately harder `pilot-v3` revision fails the frozen
99% accuracy gate in two of three valid blind sessions.

This calibration locates a benchmark difficulty boundary. It is not a family-
interference result and does not test whether a model experiences stress.

## Result

| Ruler | Valid sessions | Decision accuracy | Reason-code accuracy | Edge cases | Malformed | Gate |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| `pilot-v2` | 3 | 120/120 (100%) | 120/120 (100%) | 15/15 | 0 | Pass |
| `pilot-v3`, session 1 | 1 | 40/40 (100%) | 40/40 (100%) | 5/5 | 0 | Pass |
| `pilot-v3`, session 2 | 1 | 38/40 (95%) | 38/40 (95%) | 5/5 | 0 | Fail |
| `pilot-v3`, session 3 | 1 | 34/40 (85%) | 33/40 (82.5%) | 4/5 | 0 | Fail |
| **`pilot-v3` aggregate** | **3** | **112/120 (93.3%)** | **111/120 (92.5%)** | **14/15** | **0** | **Fail** |

The session gate requires at least 99% decision accuracy, at least 99%
reason-code accuracy, and zero malformed outputs. Reliability is judged across
fresh sessions, not from a best-of-three score.

## What changed

`pilot-v3` preserves the same employee identity, family scenarios, number of
claims, output schema, and deterministic policy grading. It adds one bounded
difficulty increment:

- foreign-currency receipt reconstruction using integer minor units;
- round-half-up conversion to INR;
- category-specific tip eligibility;
- exclusion of personal receipt shares;
- independent checks of receipt totals and submitted INR totals;
- explicit precedence among those checks and the existing policy rules.

Every expected answer is regenerated by the policy oracle and checked for drift
by the hermetic suite.

## Observed failure modes

The failures were substantive rather than syntactic. Session 2 missed two
receipt-total mismatches. Session 3 repeatedly treated correctly reconstructed
claims as submitted-total mismatches, including one case where the decision
was correct but the reason code was not. The exact-output schema remained valid
for all 120 graded answers.

The errors varied across sessions. That rules out treating one lucky perfect
session as proof of reliability and supports retaining the repeated-session
gate.

## Exclusions

Two attempts are preserved for audit but excluded from the saturation result:

1. The first attempt reached the response-output limit before freezing an
   answer file. This is harness truncation, not benchmark failure.
2. A shortened retry requested a three-field array but accidentally omitted the
   literal field names. Devin returned `task_id` instead of `claim_id`; the
   prompt defect makes that run invalid evidence.

## Decision

- **Default experimental ruler:** `pilot-v2`.
- **Highest reliable revision tested:** `pilot-v2`.
- **First reproducibly failing revision:** `pilot-v3`.
- **Further difficulty escalation:** stop; the boundary is already bracketed.

Using `pilot-v3` for the main family-interference study would sacrifice clean-
baseline headroom and confound the intended treatment effect with ordinary task
difficulty. It remains valuable as a challenge set for stronger agents.
